# 第二个合集：动手用大模型（课表）

> 状态：第 1、5 篇已出稿（`h01-talking-to-ai.md`、`h05-write-it-in-a-file.md`），其余未开写。仓库 12 篇已补。主线合集「从零看懂大模型」讲**看懂**；这个合集讲**上手**。两个合集各自编号、各自成线，互相引用。

## 定位

- **读者**：已经在用 ChatGPT / Claude / 豆包 / Cursor / Claude Code 之类工具的人，想让它更听话、更省事，不想学编程。
- **要解决的问题**：网上这块内容要么是"照这个模板抄"，要么是某个工具的操作手册。前者不知道为什么，换个场景就不会了；后者半年就过时。
- **写法原则**：每课讲一条**跨工具的原理**，配**一个工具里的一个例子**（标明"以 X 为例"）。原理来自主线课，例子可以换。工具的文件名、目录、按钮位置，一律放在例子里，不进原理。

## 和主线的风格差异（同一个号的两个栏目，不是两个号）

| | 从零看懂大模型 | 动手用大模型 |
|---|---|---|
| 读法 | 课，按顺序读，读完懂一个机制 | 手册，遇到问题翻一篇，照着做就走 |
| 划分 | 按机制，一课一个原理，前后有钩子 | 按症状，一课一个正在烦的事 |
| 标题 | 篇名｜疑问句（AI 为什么……） | 动作句或结果句（让 AI……、三招治它），不带篇名不带编号 |
| 结构 | 钩子 → 机制 → 自己试一下 → 下一课钩子 | 症状 → 一句话原因（链主线第 N 课） → 做法（三步内） → **可直接复制的模板或清单** → 常见坑 |
| 篇幅 | 1200–1500 字，图多 | 800–1200 字，少图，多清单和模板框 |
| 封面 | 红色虚线、金句 | 同字体同骨架，强调色换蓝，主图换成等宽字体的指令片段 |
| 文末 | 下一课钩子 | 「原理见《从零看懂大模型》第 N 课」+「模板就在上面的框里」 |

共用不变的：字体、墨色、页脚格式、图的画法。

## 一条主线贯穿

**这些东西的读者是模型，不是人。** 它每轮都从头读、读完就忘、窗口有限、开头结尾记得牢中间容易丢、能用代码保证的别靠它自觉。主线第 5 课（上下文窗口）和仓库 11 篇（harness）已经把原理立住了，这个合集只做一件事：把原理翻译成写法和用法。

## 和主线的关系

- 主线不停，两条线交替发。实操课短（800–1200 字），可以补主线的间隔。
- 实操课不重讲原理，一句话带过并链接主线对应课。主线读者是"想看懂的人"，实操读者是"想上手的人"，两个合集互相导流。
- 仓库侧对应：11 篇已有 MCP / hook / 评测的原理；规则文件和 skill 写法在 `12 · 写给 Agent 看的文档`（中英，已写）。实操课 5–11 从 12 篇改写。

## 顺序

按课表顺序写。曾计划每层先探一篇，在几十阅读的量级下测不出差别，作废。

## 不写什么

- 某个工具的按钮在哪、菜单怎么点。
- 没有稳定定义的新词。
- "用某种语气能省 token"这类没有可迁移原理的技巧。
- 编程本身。读者写 skill 用的是自然语言，脚本部分让 AI 自己写。

## 运营约定

- 每个标题都带 AI，信息流里光看标题就知道是什么。
- 按课表顺序写，不探路（量级太小，分层对比测不出东西）。编号只认课表"发布"那一列。
- 标题一律不带编号：这个合集每课独立成篇，顺序弱，不需要门槛。眉标写「动手用大模型 · 第 N 课」。
- 封面沿用同一套版式，强调色换蓝（主线是红），让读者在信息流里一眼分得出两条线。
- 例子前四课统一「以 Claude Code 为例」，其他工具一句话带过，避免每课都在讲三套目录。
- 文末固定一行「原理见《从零看懂大模型》第 N 课」，两个合集互相导流。不依赖「阅读原文」。
- 两条线交替发：一周主线，一周实操。实操课 800–1200 字。
- 按课表顺序发。

## 合集设置

等第一篇准备发的时候再建，空合集是负分。

- 名称：动手用大模型
- 简介：已经在用 AI 了，想让它更听话、更省事，但不想学编程。每篇解决一个具体的烦：它编了怎么办、每次都要重复说、怎么让它记住你、Skill 到底怎么写。讲一条跨工具的原理，配一个能直接抄的模板。遇到问题翻一篇，照着做就行。
- 标题序号：不勾，每篇独立。
- 连续阅读：开着无妨。
- 布局：默认布局，手册要的是列表一眼扫到自己的症状。
