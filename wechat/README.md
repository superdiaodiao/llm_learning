# 公众号版

把仓库里的章节改写成零基础读者能读的公众号文章，配图、封面、排版一并产出。

## 系列名：从零看懂大模型

合集名、封面眉标、文末页脚**一律用这一个名字**，不要出现「大模型系列」「大模型课程」这类变体——读者在信息流、封面、合集里看到的必须是同一个东西。

选它是因为它把收益说出来了：「从零」是门槛承诺，「看懂」是结果承诺。合集名在微信里显示的位置很窄，一个自带承诺的名字比一个分类标签值钱。

## 编号：公众号自己排，不跟仓库章节号挂钩

仓库 9 章是写给有工程背景的读者的；改成小白能读的版本，一章往往要拆成两到三篇。所以两边各排各的号：

| | 编号 | 面向 |
|---|---|---|
| 仓库 | `01`–`09`，固定 9 章 | 有工程背景的读者 |
| 公众号 | 第 1 课、第 2 课……顺序递增，篇数不封顶 | 零基础读者 |

**为什么不沿用仓库编号。** 硬对齐迟早会写出"第五课 中"这种标题，读者看了犯懵；而"第一课 上"本身就在暗示没写完，对信息流里的陌生读者是减分的。

序号一律用阿拉伯数字（"第 12 课"比"第十二课"好扫）。

**文件名保留仓库出处**：`01a-` = 仓库第 01 章的前半段，`01b-` = 后半段。文件名管溯源，正文里的"第 N 课"管发布。两者的对应关系写在每篇开头的引用块里。

| 文件 | 公众号 | 仓库出处 |
|---|---|---|
| `01a-why-it-cant-count-r.md` | 第 1 课 | 01 的前半段（分词） |
| `01b-word-math.md` | 第 2 课 | 01 的后半段（embedding） |
| `02a-who-bit-whom.md` | 第 3 课 | 02 的前半段（位置编码与 attention） |
| `03a-why-answers-differ.md` | 第 4 课 | 03 的前半段（logits、采样），并收进「幻觉」 |
| `03b-why-it-forgets.md` | 第 5 课 | 03 的后半段（自回归、KV cache），并收进「上下文窗口」 |
| `04a-how-it-learned-to-talk.md` | 第 6 课 | 04 的前半段（权重、loss、梯度下降、预训练） |

合集二「动手用大模型」的文件以 `h` 开头，各自编号，课表和风格约定见 `PLAN-hands-on.md`：

| 文件 | 公众号 | 原理挂 |

## 写法约定

- **开头不放系列标记。** 信息流里读者只给两秒，钩子必须是第一句。系列身份由封面眉标承担。
- **系列说明放结尾**，用 `## 关于这个系列`，会自动渲染成灰色页脚块。
- **标题 = 篇名｜钩子**（第 7 课起）。篇名是大白话的主题块，3 到 5 个字，一个篇下面三四课；
  编号不进标题，由封面眉标和合集承担。篇名 + 竖线 + 钩子压在 20 字内。

  | 篇 | 课 |
  |---|---|
  | 认字篇 | 1 分词、2 词向量 |
  | 理解篇 | 3 注意力 |
  | 生成篇 | 4 采样与幻觉、5 上下文窗口 |
  | 训练原理篇 | 6 预训练、7 对齐、8 推理、9 微调、15 规模 |
  | 成本篇 | 10 推理服务 |
  | 应用篇 | 11 RAG、12 记忆、13 Agent、14 Harness |

  为什么用篇名不用编号：编号说的是"你在第几步"，对没看过前面的人是门槛；篇名说的是"这篇讲什么"，
  对谁都是信息。而标题最左边恰恰是截断后唯一保得住的位置。篇名不能有第二种读法。两个字加"篇"没有主语："训练篇""上线篇"读起来像实操教程（那是合集二的调性），"成长篇""炼成篇"读起来像读者自己的成长。所以训练那一块写全"训练原理篇"，"原理"两个字排除实操和读者成长两种误读；认字、理解、生成、成本、应用的主语从语义上只能是 AI，不用加。用大白话，不写"预训练"。

  前 6 课发布时标题是"第 N 课｜"或不带前缀（当时在做交替测试）。已群发文章标题只能改 3 个字，
  这 6 篇都动不了，用**摘要**补篇名，格式同下。
- **摘要 = 篇名 · 第 N 课。一句话结论。** 单图文推送在会话列表里摘要显示在标题下面，是标题之外唯一能带篇名的位置。
  已群发文章每篇只能修改一次（标题 3 字、正文 120 字、图片 3 张、封面 1 张、摘要总长 120 字内），
  改摘要时把正文错别字一并改掉。
- **不依赖「阅读原文」**（编辑器里已经没有这个入口）。目录由合集承担，模板直接放正文的框里；仓库地址若要给，只能当纯文字放页脚，读者复制。
- **同一课可以发两次**：长文章讲透、进合集；隔几天把同一批卡片发成**图片消息**（正文 1000 字上限），
  触达不点长文的人。短文案直接用 `xhs/` 里那份，两边通用。

## 出稿

```bash
# 正文 → 可直接粘贴进公众号编辑器的行内样式 HTML
python3 wechat/build-paste-html.py wechat/01a-why-it-cant-count-r.md

# 合集二：蓝色主题，围栏代码块会变成可复制的模板框
python3 wechat/build-paste-html.py --blue wechat/h01-talking-to-ai.md

# 封面（2.35:1 首图 + 1:1 方图，两版分别构图，不能靠裁）
python3 wechat/build-cover.py 5      # 主线第 5 课
python3 wechat/build-cover.py h1     # 合集二第 1 篇（蓝色、勾选框、指令片段）
rsvg-convert -w 1800 -o images/wx1_cover.png        images/wx1_cover.svg
rsvg-convert -w 1200 -o images/wx1_cover_square.png images/wx1_cover_square.svg

# 插图
rsvg-convert -w 1558 -o images/wx1_xxx.png images/wx1_xxx.svg
```

生成的 `*.paste.html` 用浏览器打开，点「复制正文」，到编辑器里粘贴。公众号编辑器会剥掉 `<style>` 标签和 class，只认元素上的行内 `style`，所以不能直接贴 Markdown。

转换脚本认 `##` 小标题、`**粗体**`、`` `代码` ``、列表、图片，会跳过开头的引用块。`build-paste-html.py` 顶部两个常量控制特殊样式：`BOXED`（高亮框，给要读者动手的段落）和 `TAIL`（灰色页脚块）。

## 配图

- 插图 `images/wx1_*.png`，1558px 宽，与仓库其余图同规格同配色。
- 图片必须在公众号编辑器里上传，微信会把图片地址重写到自己的 CDN，外链图发出去是空的。
- 转换脚本会在图片位置留虚线占位框，框里写着对应文件名。

依赖 `librsvg2-bin` 和 `fonts-noto-cjk`——少了后者，中文会掉到别的字体，跟仓库其余图对不上：

```bash
apt-get install -y librsvg2-bin fonts-noto-cjk
```
