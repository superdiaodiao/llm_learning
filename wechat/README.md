# 公众号版

把仓库里的章节改写成零基础读者能读的公众号文章，配图、封面、排版一并产出。

## 编号：公众号自己排，不跟仓库章节号挂钩

仓库 9 章是写给有工程背景的读者的；改成小白能读的版本，一章往往要拆成两到三篇。所以两边各排各的号：

| | 编号 | 面向 |
|---|---|---|
| 仓库 | `01`–`09`，固定 9 章 | 有工程背景的读者 |
| 公众号 | 第 1 课、第 2 课……顺序递增，篇数不封顶 | 零基础读者 |

**为什么不沿用仓库编号。** 硬对齐迟早会写出"第五课 中"这种标题，读者看了犯懵；而"第一课 上"本身就在暗示没写完，对信息流里的陌生读者是减分的。

序号一律用阿拉伯数字（"第 12 课"比"第十二课"好扫）。

**文件名保留仓库出处**：`01a-` = 仓库第 01 章的前半段，`01b-` = 后半段。文件名管溯源，正文里的"第 N 课"管发布。两者的对应关系写在每篇开头的引用块里。

| 文件 | 公众号 | 仓库出处 |
|---|---|---|
| `01a-why-it-cant-count-r.md` | 第 1 课 | 01 的前半段（分词） |

## 写法约定

- **开头不放系列标记。** 信息流里读者只给两秒，钩子必须是第一句。系列身份由封面眉标承担。
- **系列说明放结尾**，用 `## 关于这个系列`，会自动渲染成灰色页脚块。
- **标题不加系列前缀。** 信息流里标题二十来字就截断，前缀会把钩子挤掉。分组交给公众号自带的「合集」功能。
- **「阅读原文」挂仓库地址**，公众号正文里的外链点不动，这是唯一的出口。

## 出稿

```bash
# 正文 → 可直接粘贴进公众号编辑器的行内样式 HTML
python3 wechat/build-paste-html.py wechat/01a-why-it-cant-count-r.md

# 封面（2.35:1 首图 + 1:1 方图，两版分别构图，不能靠裁）
python3 wechat/build-cover.py
rsvg-convert -w 1800 -o images/wx1_cover.png        images/wx1_cover.svg
rsvg-convert -w 1200 -o images/wx1_cover_square.png images/wx1_cover_square.svg

# 插图
rsvg-convert -w 1558 -o images/wx1_xxx.png images/wx1_xxx.svg
```

生成的 `*.paste.html` 用浏览器打开，点「复制正文」，到编辑器里粘贴。公众号编辑器会剥掉 `<style>` 标签和 class，只认元素上的行内 `style`，所以不能直接贴 Markdown。

转换脚本认 `##` 小标题、`**粗体**`、`` `代码` ``、列表、图片，会跳过开头的引用块。`build-paste-html.py` 顶部两个常量控制特殊样式：`BOXED`（高亮框，给要读者动手的段落）和 `TAIL`（灰色页脚块）。

## 配图

- 插图 `images/wx1_*.png`，1558px 宽，与仓库其余图同规格同配色。
- 图片必须在公众号编辑器里上传，微信会把图片地址重写到自己的 CDN，外链图发出去是空的。
- 转换脚本会在图片位置留虚线占位框，框里写着对应文件名。

依赖 `librsvg2-bin` 和 `fonts-noto-cjk`——少了后者，中文会掉到别的字体，跟仓库其余图对不上：

```bash
apt-get install -y librsvg2-bin fonts-noto-cjk
```
