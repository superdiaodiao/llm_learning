# 每次都要跟 Claude Code 重复的话，写进一个文件

> 合集二「动手用大模型」规划位第 5 篇（规则层第一篇），发布顺序第 2 篇，摘要按发布顺序编号。以 Claude Code 为例，兼顾 Codex / Cursor，另给聊天 App（豆包、Kimi、ChatGPT、WorkBuddy）的做法和模板。原理挂主线第 5 课，写法来自仓库 12 篇。约 1000 字。生成 HTML 用 `--blue`。

你有没有这种话，每开一个新对话都要说一遍：

"用中文回复。""这个项目用 uv，别用 pip。""测试命令是 `uv run pytest`。""`migrations/` 里的文件别动。"

忘了说，它就猜。猜错了，重来。

## 为什么它记不住

它每一轮只看窗口里的东西，新开的对话窗口是空的，上次说的什么都不在（主线第 5 课）。它不是不听话，是真的没看见。

工具留了一个口子：**一个固定的文件，每一轮开始时自动读进窗口。**写进去的话，你就再也不用说了。

这个文件放哪？**放在你打开 AI 时所在的那个文件夹里。**你让 Claude Code 帮你处理哪个文件夹的东西，就把文件放在那个文件夹里。它每次在这个文件夹里干活，都会先读这个文件。

三个常用工具里它叫不同的名字：Claude Code 叫 `CLAUDE.md`，Codex 叫 `AGENTS.md`，Cursor 放在 `.cursor/rules/` 文件夹里。

（还有一个"个人文件"，放在你电脑的用户主目录，你去任何文件夹它都跟着。像"用中文回复"这种你在哪都想要的习惯可以放那里。刚开始不用管它，一个文件够用；等你在好几个文件夹里用 AI、或者有同事一起用同一个文件夹，再分。）

下面以 Claude Code 为例，换成你的工具只是文件名不同。

## 三步

**1. 在那个文件夹里建一个文件。** 新建 `CLAUDE.md`（Codex 是 `AGENTS.md`）；或者在对话里输入 `/init`，它会看一遍这个文件夹自动生成一份初稿，你再删改。Claude Code 和 Codex 都有这个命令。

**2. 只写四类东西。** 怎么跑（确切的命令）、目录在哪（五到十行）、跟别处不一样的约定、禁区。判断标准一句话：**它自己发现不了、又每次都需要的**，才写。

**3. 写完放着别管，出问题再加。** 它猜错一次，你就补一条；补的时候问一句"这是每次都需要的吗"，不是就别加。文件是给这个文件夹里所有用 AI 的人看的，如果有同事一起用，别把"用中文回复"这种自己的习惯写进去，那是个人文件的事。

## 直接复制

```
# 这个文件夹的规矩

## 运行
- 安装：`uv sync`；测试：`uv run pytest -q`；起服务：`uv run uvicorn app.main:app`
- 提交前跑 `uv run ruff check .`，红了别提交

## 结构
- `app/` 业务代码，`app/api/` 路由，`app/core/` 领域逻辑
- `tests/` 与 `app/` 同构；`migrations/` 由工具生成，别手改

## 约定
- 包管理只用 uv，不用 pip
- 提交信息格式：`type(scope): 一句话`

## 禁区
- 不改 `migrations/` 里已有文件；不删 `tests/` 里的用例
- 涉及 `.env`、密钥、生产配置的改动先问人
```

把命令、目录、约定换成你自己的。删掉不适用的行，别留空板块。二十来行是正常长度，超过五十行要警惕。这一份是给 Claude Code 这类会碰文件夹的工具的；聊天 App 用下一节那份。

## 不用 Claude Code？豆包、Kimi 也有这个口子

你如果用的是豆包、Kimi、ChatGPT、WorkBuddy 这类不需要文件夹的工具，没有 `CLAUDE.md`，但同一个口子换了个样子：**设置里的"个性化""自定义指令""系统提示"这类入口。**写在那里的话，每个新对话开始时它一样会先读。不同 App 名字不一样，到设置里找这几个词。

实在找不到，有一个在任何工具里都管用的笨办法：把那段话存进备忘录，**每个新对话的第一条消息粘上去。**效果一样，就是多一步。

内容也换一换。聊天工具没有"怎么跑""目录在哪"，四类变成：你是谁、要什么风格、固定的输出格式、禁区。

```
关于我：做市场的，不懂技术，看的东西要给不懂技术的同事转述。
风格：用中文；先给结论再给理由；不要客套话，不要"当然可以"开头。
格式：超过三点用列表；给数字要说来源；不确定的直接说不确定。
禁区：不要替我编数据；不要在我没问的时候扩展话题。
```

## 常见坑

- **写成教科书。** "Python 用四空格缩进""变量名要清晰"。这些它比你熟，写进去只占地方，还稀释了真正重要的那几行。只写和通用做法**不一样**的。
- **越写越长。** 每出一次问题加一条，半年后两百行，它对每一行的注意力都被摊薄了。每加一条问一句"这是每一轮都需要的吗"，不是就删。
- **写会变的东西。** 版本号、正在做的功能、这周的临时安排。过时的规则比没有规则更糟，它会照着错的做。
- **把"别删文件"当保险。** 写在文件里它多半会照做，但"多半"不是"一定"，聊长了它可能忘。真正要保证的事，得用代码拦，后面 Hook 那篇讲。
